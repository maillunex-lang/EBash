# Работа с проектом

Единые правила для любых ИИ-исполнителей (Claude, ChatGPT/Codex, Grok, Copilot, Cursor и др.). `CLAUDE.md` и `.github/copilot-instructions.md` только ссылаются сюда.

## Маршрут чтения (экономия токенов)

1. Известен ID задачи → сразу `docs/tasks/<ID>.md`, затем только ссылки из её раздела «Читать».
2. ID неизвестен → `docs/STATUS.md` (что сейчас в приоритете) → `docs/tasks/INDEX.md`.
3. Нужен документ по теме → таблица в `docs/READING.md`, полный список — `docs/INDEX.md`.
4. Решения проверяй точечно: `rg -n 'D-042' docs/decisions/001-foundation.md`. Весь реестр не читай.
5. Структура файла без чтения: `rg -n '^## ' <файл>`. Не читай всё рекурсивно.

| Каталог | Что внутри |
| --- | --- |
| `docs/decisions/` | Реестр утверждённых решений (D-NNN) |
| `docs/gdd/` | Профильные разделы GDD: правила и помеченные предложения |
| `docs/tasks/` | Очередь и файлы задач (DES-NNN) |
| `prototypes/` | Сравнительные прототипы Godot/Unity, см. их README |
| `.agents/skills/` | Навыки-инструкции для типовых операций (также `.claude/skills`) |
| `scripts/check_docs.py` | Проверка ссылок, ID решений и графа задач |

## Правила

- Утверждено только то, что есть в реестре решений. Не выдавай предложения и открытые вопросы за требования.
- Не выбирай самостоятельно название, сюжет, стек, монетизацию, масштаб первой версии и коэффициенты: это решает владелец.
- Перед реализацией проверь зависимости и приёмку задачи. Если их нет, задача не готова.
- Не задавай повторно решённые вопросы: сначала найди ID в реестре. Задачи проектирования готовят предложение, но не утверждают правила.
- Каждый факт подробно описан в одном профильном документе; в остальных местах — ссылка. Формулы в задачи и журналы не копируй.
- Документы и обсуждение — на русском. ID задач и решений стабильны.
- При добавлении документа обнови `docs/INDEX.md`; после изменения документации запусти `python3 scripts/check_docs.py` из корня.

## Навыки

- `ebash-task` — взять и выполнить задачу из очереди.
- `ebash-decision` — записать решение владельца в реестр и GDD.
- `ebash-prototype` — собрать и проверить прототипы.
