# Работа с проектом

Единые правила для любых ИИ-исполнителей (Claude, ChatGPT/Codex, Grok, Copilot, Cursor и др.). `CLAUDE.md` и `.github/copilot-instructions.md` только ссылаются сюда.

## Маршрут чтения (экономия токенов)

1. **Передача работы другому ИИ:** сначала [краткая передача](docs/HANDOFF.md) и [актуальный статус](docs/STATUS.md), но при известной задаче переходи сразу к её файлу. Не читать оба повторно для каждой подзадачи.
2. Известен ID задачи → сразу `docs/tasks/<ID>.md`, затем только ссылки из её раздела «Читать».
3. ID неизвестен → `docs/STATUS.md` (что сейчас в приоритете) → `docs/tasks/INDEX.md`.
4. Нужен документ по теме → таблица в `docs/READING.md`, полный список — `docs/INDEX.md`.
5. На текущем VPS **нет установленного `rg`**, поэтому использовать `grep` (а для списка файлов `find`). Решения проверяй точечно: `grep -n 'D-042' docs/decisions/001-foundation.md`. Весь реестр не читай.
6. Структура файла без чтения: `grep -n '^## ' <файл>`. Не читай всё рекурсивно.

| Каталог | Что внутри |
| --- | --- |
| `docs/decisions/` | Реестр утверждённых решений (D-NNN) |
| `docs/gdd/` | Профильные разделы GDD: правила и помеченные предложения |
| `docs/tasks/` | Очередь и файлы задач (DES-NNN) |
| `prototypes/` | Прототипы; выбран Godot (`prototypes/godot`), Unity — только для истории |
| `.agents/skills/` | Навыки-инструкции для типовых операций (также `.claude/skills`) |
| `scripts/check_docs.py` | Проверка ссылок, ID решений и графа задач |

## Правила

- Утверждено только то, что есть в реестре решений. Не выдавай предложения и открытые вопросы за требования.
- Не выбирай самостоятельно название, сюжет, стек, монетизацию или масштаб первой версии: это решает владелец. **Исключение:** рабочие параметры и баланс только DES-003 делегированы в D-149; нельзя распространять делегирование на новые концептуальные правила или другие задачи.
- Перед реализацией проверь зависимости и приёмку задачи. Если их нет, задача не готова. Завершённые DES-001/002/003 означают готовые **спецификации**, а не написанный сервер.
- **Граница публикации:** работать только в `/home/gamedev/ebash-main` на VPS Lunex. Никаких `git fetch/pull/push/clone`, GitHub API, PR или синхронизации без новой отдельной команды владельца. Не трогать другие проекты, сервисы и ключи VPS; не удалять незакоммиченные файлы.
- Черновые рецепты `docs/catalogs/recipes.seed.json` по D-139 **неисполняемы**, без норм и источников. Число 100+ в графе не означает готовность каталога.
- Не задавай повторно решённые вопросы: сначала найди ID в реестре. Задачи проектирования готовят предложение, но не утверждают правила.
- Каждый факт подробно описан в одном профильном документе; в остальных местах — ссылка. Формулы в задачи и журналы не копируй.
- Документы и обсуждение — на русском. ID задач и решений стабильны.
- При добавлении документа обнови `docs/INDEX.md`; после изменения документации запусти `python3 scripts/check_all.py` из корня (включает проверку ссылок, каталогов, передачи и рыночных сценариев). Не добавляй в краткий статус хронологические абзацы: историю хранить в задачах/реестре.

## Навыки

- `ebash-task` — взять и выполнить задачу из очереди.
- `ebash-decision` — записать решение владельца в реестр и GDD.
- `ebash-godot` — клиентский код на Godot.
- `ebash-android-build` — сборка APK и проверка на телефоне.
- `ebash-prototype` — общие правила `prototypes/`, судьба Unity.
