# Работа с EBash

1. Проверь `git status --short`. Рабочая копия находится на Lunex в `/home/gamedev/ebash-main`. Сохраняй чужие изменения.
2. Если задача известна, открой её файл или строку в [маршрутах чтения](docs/READING.md). При передаче без конкретной задачи открой [HANDOFF](docs/HANDOFF.md).
3. Читай только нужные разделы. `grep -n '^## ' файл` найдёт заголовки, `grep -n 'D-125' docs/decisions/001-foundation.md` найдёт решение. На Lunex используй `grep` и `find`, если `rg` недоступен.
4. Перед работой проверь зависимости и критерии приёмки. После правок запусти профильные проверки из [маршрутов](docs/READING.md) и `git diff --check`.

## Правила

- Утверждённые правила хранятся в [реестре](docs/decisions/001-foundation.md). D-181 делегирует обоснованные решения разработки. Фиксируй новые правила и условия проверки в реестре и профильном документе. Помечай допущения и предложения.
- D-192: развивай только игровой клиент против сервера. Не планируй и не дорабатывай локальный UI-стенд, «демозавод» и сравнение движков. Автопроверки с тестовым миром — это проверки игры.
- GitHub fetch/pull/push/clone, PR, смена remote и синхронизация требуют отдельной команды владельца. Разрешение на одну публикацию действует для порученного пакета. Другие проекты, службы и ключи Lunex оставь владельцу.
- По D-139 черновые операции каталога до подтверждения обязательных профилей заблокированы. Игровые данные пилота и проверенные производственные нормы учитывай раздельно.
- Пиши документацию на русском. Сохраняй ID задач и решений. Подробности держи в профильном документе, в остальных местах давай ссылку. Добавляй новые документы в [индекс](docs/INDEX.md). Для изменений в документации запусти `python3 scripts/check_all.py`.
