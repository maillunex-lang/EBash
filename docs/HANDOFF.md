Назначение: короткая воспроизводимая точка входа. **Не читать весь GDD/реестр/логи подряд.** Текущий статус: [STATUS](STATUS.md). Сводка действующих правил: [QUICK-REFERENCE](gdd/QUICK-REFERENCE.md). Запись следующих задач: [очередь](tasks/INDEX.md). Выбор профильного документа: [READING](READING.md).

## Безопасная граница работы

- Проект: **только EBash**, `/home/gamedev/ebash-main` на VPS Lunex. Другие проекты, Docker, сервисы и ключи не трогать.
- **GitHub запрещён** до отдельного указания владельца. Не выполнять `git pull`, `git fetch`, `git push`, `git clone`, создание PR, изменения remote или автосинхронизацию. Локальные проверки `git status`, `git diff --check` разрешены. Не пытаться «очистить дерево» удалением файлов.
- На VPS уже есть незакоммиченные изменения. Нельзя считать локальный `main` опубликованным на GitHub. Перед любыми правками изучить `git status --short`, сохранить существующую работу.
- Приоритет: спецификации, затем после закрытия зависимостей архитектура и код. Не выдавать ранний прототип за игровую бету или APK релиза.
- Без платных API и фонового LLM на VPS.

## Реальная готовность

- Выполненные DES-001/002/003 означают **документацию**, не производственный сервер и не готовый баланс. У DES-003 рабочие коэффициенты v1 по разрешению D-149, их необходимо перепроверить после появления товарных профилей.
- `docs/catalogs/recipes.seed.json`: 108 **неисполняемых** предложений; количество и типы входов приблизительны, технологические нормы `null`; потенциальные ошибки в физике побочных продуктов и нефтепереработки требуют проверки.
- `docs/catalogs/resources.seed.json`: 136 **черновых** ID, включая участки и коммунальную энергию; названия не гарантируют единицу измерения или источник данных.
- `scripts/check_des004_catalog.py` проверяет ссылки, уникальность, ацикличность чернового графа и fail-closed, **не подтверждает технологическую корректность**.
- Godot-прототип в `prototypes/godot/`; версия клиента 4.7.2, исторические проверки прототипа проводились на другой версии. Unity-прототип оставлен как исторический, не развивать.

## Последовательность действий

1. Выбрать **одну** разблокированную задачу; зафиксировать её границы и читать только профильные разделы.
2. Сверить нужные утверждённые решения (D-NNN) и зависимости; новые концептуальные изменения только после разрешения владельца.
3. Для DES-004 сначала подготовить проверяемые типы и единицы; затем отобрать реальные технологические источники и оформить численные профили, источники, выполнимые 3×3 стадии. Не подменять нормы догадками. Список городов с реальными сведениями подтверждать источниками; не заявлять фиктивные координаты/население.
4. Обновлять один профильный GDD или индекс каталога и файл задачи, **не добавлять очередные абзацы-«обновления статуса» в конец `STATUS.md`**.
5. Запустить единую локальную проверку `python3 scripts/check_all.py`, затем `git diff --check`. При внесении новых файлов обновить индекс навигации и релевантные проверки.
6. Отчитаться: изменённые файлы, статус, тесты, открытые вопросы, **без публикации**.

## Что не считать выполненным

- 108 черновиков ≠ 108 готовых рецептов. Источники, баланс массы, выходы, роли 3×3 и города открыты.
- Зелёная проверка Markdown ≠ отсутствие ошибок в игре или работоспособность APK.
- Владелец отдельно делегировал **рабочий баланс DES-003**, не любые будущие принципы экономики и не публикацию на GitHub.
