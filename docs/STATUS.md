**Последний подтверждённый аудит:** `python3 scripts/check_all.py`, `go test -race ./...`, изолированный PostgreSQL `bash server/check_p32_postgres.sh` прошли. Не проверены полноценный Android-проход, длительная нагрузка и все производственные цепочки. [Детали и риски](audits/2026-11-18.md).

**Текущий фокус альфы:** E-104, сквозная торговая интеграция в изолированном мире, после защит E-101–103; затем E-106 Android. [Повторный аудит 18.11](audits/2026-11-18-full-project-followup.md).

**Следующий пакет:** E-101 и E-102 частично выполнены (защита переполнений, атомарное применение планов и общий бюджет разных одноэтапных линий), продолжается E-103 и проверки внутренних веток планировщика, затем интеграция со складом/резервами/доставкой/продажами в изолированном мире, затем Android. [Приоритеты](roadmap/implementation-backlog.md).

**Границы:** только `/home/gamedev/ebash-main` на VPS Lunex; GitHub не трогать без отдельной команды. Никаких удалений `.local` или изменений чужих сервисов. [AGENTS](../AGENTS.md) · [HANDOFF](HANDOFF.md).

**18.11, E-102:** крупные группы 9+ теперь имеют ограниченный 100 мс поиск допустимого ненулевого плана; если поиск не доказал оптимальность, статус явно помечен. Это не завершает DES-002.

**E-103 (частично):** проверка и атомарность каждого промежуточного этапа производственной цепочки усилены, тест переполнения склада пройден; глобальный планировщик ещё не завершён.

**E-102, уточнение:** реализован явный tie-break D-115 по ID при равенстве выпуска и квот; устранён риск промежуточного переполнения в расчёте дробных квот. Глобальный оптимизатор цепочек остаётся открытым.

**E-102, D-116:** исходные квоты всех производственных линий фиксируются до первого этапа; новые промежуточные остатки доступны следующим этапам без пересчёта квот. Тесты пройдены, глобальная оптимальность не доказана.

**E-101:** устранены переполнения при загрузке профилей рецептов (масса, выходы, потери); 4 новых теста. E-102 глобальный межстадийный оптимум всё ещё не реализован.

**E-102, поиск:** добавлено безопасное отсечение заведомо проигрышных ветвей с сохранением равных по выпуску вариантов для квот и ID. Проверки пройдены; глобальная межстадийная оптимальность остаётся открытой.

**E-104 (начат, изолирован):** модель лотов и резерва с правилами T+1 и атомарной отгрузкой; интеграция с PostgreSQL/HTTP/производственным состоянием ещё отсутствует.

**E-104:** в автономном складском модуле производство теперь расходует только созревшие незарезервированные лоты, атомарно; пока без интеграции с серверными транзакциями.

**E-104, PostgreSQL:** опциональный `gameProductionState.Inventory` транзакционно синхронизирован с Stock и Cash в изолированном тике; тесты T+1, резервирования и повторного тика на PostgreSQL PASS. Реальный торговый API ещё не подключён.
