# EBash: повторный аудит структуры, кода и маршрутов ИИ (18.11.2026)

## Область и честные ограничения

- Проверены структура 173 файлов исходников/документов в `.agents`, `docs`, `prototypes`, `scripts`, `server`, `web` (без `.git`, `.local`, `.godot`, Python-окружений и кэшей), чтение UTF-8, JSON, пустые исходники, компиляция Python, Go tests/vet, изолированные PostgreSQL тесты и headless Godot-пилот.
- `server/.local` занимает гигабайты, включая старые изолированные каталоги PostgreSQL. **Ничего не удалено:** содержимое не является исходным кодом и требует отдельной политики хранения/проверки процессов.
- Проверки не заменяют ручную Android-приёмку, security pentest, длительный нагрузочный тест, все игровые ветви и полноту промышленной верификации рецептур. Сторонние системные службы и GitHub не изменялись.

## Исправления и подтверждения

1. **Найден и исправлен пробел CI:** `scripts/check_all.py` не запускал 7 новых DES-004 проверок (зерно, баланс, мебель, магазины). Теперь они включены в общий офлайн-пакет; добавлен структурный аудит `scripts/audit_project_inventory.py`.
2. **Маршрутизация ИИ:** `docs/READING.md` содержит точечные маршруты; `docs/STATUS.md` и `docs/roadmap/stages.md` приведены к состоянию «пилот подтверждён, полная альфа не готова». Длинные исторические документы не удалялись и не дублировались.
3. **Каталоги:** исходные 105 рецептов/139 ресурсов остаются черновиками; 3 утверждённых игровых хлебных профиля отдельны. 16 зерновых сценариев, 8 мебельных операций и 9 типов магазинов с 45 предварительными розничными SKU пока **не исполняются**.
4. **Тесты:** `go test ./...`, `go vet ./...`, `python3 -m compileall -q scripts`, `bash server/check_p32_postgres.sh` и `EBASH_PILOT_MODE=demo-smoke bash server/check_godot_pilot.sh` (с переменными путей к установленным бинарникам) прошли. Последний тест подтвердил 2 производственные партии в отдельном демомире, не сквозную торговлю.

## Открытые риски и приоритеты

| Приоритет | Риск / незавершённое | Следующее действие |
| --- | --- | --- |
| P0 | E-101–103: глобальная оптимальность связанных линий, ограничения 3×3, полная защита от переполнений | Дополнить серверные инварианты и негативные тесты |
| P0 | E-104: новые лоты/резервы связаны с изолированным производственным состоянием, но не с реальными HTTP-операциями поставок/магазина | Сквозной изолированный PostgreSQL+HTTP тест закупка→производство→доставка→магазин→продажа T+1 |

| P2 | Рост `.local` и накопление PostgreSQL-тестовых папок | Отдельный read-only аудит процессов/сроков хранения, затем согласованная безопасная очистка |

## Маршрут для следующего ИИ

`AGENTS.md` → `docs/READING.md` → **одна строка** `docs/roadmap/implementation-backlog.md` → файлы конкретной задачи. Не читать этот аудит, весь GDD, `DES-004-history.md` и `server/.local` при обычных задачах. После изменений выполнить профильные тесты, `python3 scripts/check_all.py`, `git diff --check`. Историю хранить в профильном протоколе, а не копировать в `STATUS.md`.
